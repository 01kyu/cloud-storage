# Соглашения по коду

Линтеры закрывают синтаксис и форматирование. Здесь — то, что они не проверяют: как читается код
и что в нём не должно появляться.

## Комментарии

Оставляем только то, что нельзя узнать из кода.

- «Почему» вместо «что»: обход бага браузера, ограничение платформы, договорённость с бэкендом,
  неочевидный порядок шагов.
- Не комментируем очевидное. `/** Экран входа */` над `LoginView`, `/** Эндпоинты файлов */` над
  `fileApi`, `// создаём папку` перед `createFolder` — шум, который через месяц только мешает.
- JSDoc — для экспортируемого API, где важны границы: `null` = корень, единицы измерения, побочные
  эффекты. Не для пересказа имени функции и не для описания вёрстки компонента.
- Максимум 1–2 строки. Абзац в комментарии — признак того, что либо код непонятен, либо это место
  документации, а не исходника.
- Временное состояние в комментарии не фиксируем: ни «сделаем в следующей итерации», ни номеров
  этапов, ни ссылок на план. Комментарий должен быть верен и через год.
- `TODO` без задачи и исполнителя не оставляем: незаконченное либо делается, либо не попадает
  в коммит. Закомментированного кода тоже нет — для истории есть git.

Проверка простая: открой файл через неделю. Если комментарий ничего не добавил к тому, что видно
в коде, — удаляй.

## Имена

- Имя отвечает на вопрос «что это»: `useUploadFiles`, `getQuotaPercent`, `node-actions.tsx`.
- Без `data`, `info`, `helper`, `utils`, `manager` — они не сообщают ничего.
- `use*` — только хуки, `*Api` — только объект эндпоинтов, `*Props` — только пропсы компонента.

## Структура

- Один файл — одна причина меняться. Если файл нужно объяснять абзацем, его пора делить.
- Наружу — только через `index.ts` слайса.
- Магическое число живёт в именованной константе рядом с использованием.

## Тесты

- Имя теста читается как требование: `it("удаляет файл в корзину")`. Без `should`, `tests`, `case 1`.
- Docblock над `describe` не нужен: имя сьюта описывает сценарий лучше.
- Комментарий внутри теста — только про неочевидное (`baseQuery` ретраит `FETCH_ERROR`, поэтому
  таймаут больше).

## Тексты интерфейса

- По-русски, с «ё», без канцелярита.
- Ошибка = что случилось + что делать. Без кодов и внутренних терминов.
- Без «Пожалуйста» и извинений за ошибку.

## Коммиты

- `тип: действие` — `feat: загрузка и действия над файлами`, `fix: …`, `refactor: …`, `test: …`,
  `chore: …`.
- Тело — только «почему». Списки файлов, метрики покрытия и перечисление шагов не нужны: это видно
  в диффе и CI.
- Один коммит — одна причина меняться.

## README и документация

README описывает продукт: что это, как запустить, какие переменные окружения нужны. Внутренние
планы, заметки и статусы итераций в репозиторий не попадают.
